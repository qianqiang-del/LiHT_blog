# 前台标签模块接口设计

> 版本：v1.0
> 范围：前台 Web 端「标签模块」（标签云/侧边栏 + 标签文章列表页）
> 关联原型：`prototype-final.html`
> 约定：**响应 / 错误码 / 分页全部复用基建**（`pkg/response`、`pkg/errors`、`response.PageRequest/PageResponse`），与首页（v1.2）、分类模块（v1.0）设计风格一致。

---

## 1. 基建约定（必须复用，禁止自定义）

- **统一响应**：`response.Success(c, data)` → `{ "code": 0, "message": "成功", "data": ... }`
- **错误**：`response.BadRequest(c, msg)`（400）、`response.BizError(c, err)`（业务错误，取 `BizError.Code/Message`）
- **分页请求**：`response.PageRequest{ Page int(form:"page"), Size int(form:"size") }`，**`page`/`size` 标注 `required`，前端必传**
- **分页响应**：`response.PageResponse{ List, Total, Page, Size, TotalPage }`，由 `response.NewPageResponse(list, total, page, size)` 构造
- **错误码**：`errors.CodeSuccess=0`、`CodeBadRequest=400`、`CodeResourceNotFound=3001`、`CodeInternalError=500`；业务错误用 `errors.New(code, msg)` / `errors.NewDefault(code)`

> 标签列表不分页（数据量小），用普通 GET；标签文章列表复用 `response.PageRequest` 分页。

## 2. 接口契约（2 个核心 GET，均为公开接口）

基础前缀：`/api/v1`

### 2.1 标签列表（标签云 / 侧边栏）

`GET /api/v1/tags`

**说明**：返回全部标签及其已发布文章数，按文章数**降序**（热度优先），同热度按 `id` 升序。

**Response（data 为 `[]TagItem`）**
```json
{
  "code": 0,
  "message": "成功",
  "data": [
    { "id": 3, "name": "Go", "article_count": 8 },
    { "id": 5, "name": "Vue", "article_count": 5 }
  ]
}
```

`TagItem` 结构：
```json
{ "id": 3, "name": "Go", "article_count": 8 }
```

### 2.2 标签下的文章列表（标签详情页）

`GET /api/v1/tags/:id/articles`

**路径参数**

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | uint | 是 | 标签 ID |

**Query 参数（复用 `response.PageRequest`）**

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `page` | int | 是 | 页码 |
| `size` | int | 是 | 每页条数，≤100 |
| `sort` | string | 否 | `latest`（默认，按 `published_at` 倒序）/ `hot`（按 `hot` 倒序） |

**Response（data 为 `response.PageResponse`，`list` 为 `[]ArticleListItem`）**
```json
{
  "code": 0,
  "message": "成功",
  "data": {
    "list": [ /* ArticleListItem[] */ ],
    "total": 8,
    "page": 1,
    "size": 10,
    "total_page": 1
  }
}
```

> `ArticleListItem` 结构见首页接口设计文档 §2.4。
> 只查 `status=1`（已发布）；标签不存在返回 `CodeResourceNotFound`。
> 多对多实现：`article_tags` 表（`article_id` + `tag_id` 复合主键）。

## 4. 分层实现设计

### 4.1 新增目录结构

```
internal/
  dto/
    tag.go           # TagItem（新增）
    article.go       # ArticleListRequest / ArticleListItem（已存在，复用）
  repository/
    tag_repository.go        # 标签 + 文章数统计（新增）
  service/
    tag_service.go           # 标签列表 / 校验存在（新增）
  api/
    tag_controller.go        # 2 个 GET 的 controller（新增）
```

> 文章查询复用现有 `ArticleService.ListArticles(req)`（`article_repository.ListPublished` 需支持 `tag_id` 筛选，见 §4.3 说明）。

### 4.2 DTO（`internal/dto/tag.go`）

```go
package dto

type TagItem struct {
    ID           uint  `json:"id"`
    Name         string `json:"name"`
    ArticleCount int64 `json:"article_count"`
}
```

### 4.3 Repository 层

```go
// repository/tag_repository.go
type TagRepository interface {
    // 全部标签 + 各标签「已发布」文章数（LEFT JOIN article_tags + articles 聚合，按计数降序）
    ListWithCount() ([]dto.TagItem, error)
    // 校验标签是否存在（供 :id/articles 使用）
    Exists(id uint) (bool, error)
}
func NewTagRepository(db *gorm.DB) TagRepository
```

> `ListWithCount` 实现示例：
> ```sql
> SELECT t.id, t.name, COUNT(a.id) AS article_count
> FROM tags t
> LEFT JOIN article_tags at ON at.tag_id = t.id
> LEFT JOIN articles a ON a.id = at.article_id AND a.status = 1
> GROUP BY t.id, t.name
> ORDER BY article_count DESC, t.id ASC;
> ```

> **前置依赖**：`article_repository.ListPublished` 需支持 `tag_id` 参数——实现时 `JOIN article_tags ON article_tags.article_id = articles.id AND article_tags.tag_id = ?`，并去重（`SELECT DISTINCT` 或 `GROUP BY articles.id`）。

### 4.4 Service 层

```go
// service/tag_service.go
type TagService interface {
    ListTags() ([]dto.TagItem, error)
    TagExists(id uint) (bool, error)
}
```

> 标签文章列表**不**在此新增方法，直接复用 `ArticleService.ListArticles`：
> controller 构造 `dto.ArticleListRequest{ PageRequest:{page,size}, Sort:sort, TagID:id }` 调用即可。

### 4.5 Controller 层（全部走 `pkg/response`）

```go
// api/tag_controller.go
type TagController struct {
    tagSvc    service.TagService
    articleSvc service.ArticleService
}
func NewTagController(tagSvc service.TagService, articleSvc service.ArticleService) *TagController
func (c *TagController) RegisterRoutes(g *gin.RouterGroup) {
    g.GET("/tags", c.ListTags)                   // 2.1
    g.GET("/tags/:id/articles", c.TagArticles)   // 2.2
}

func (c *TagController) ListTags(ctx *gin.Context) {
    list, err := c.tagSvc.ListTags()
    if err != nil {
        response.BizError(ctx, err)
        return
    }
    response.Success(ctx, list)
}

func (c *TagController) TagArticles(ctx *gin.Context) {
    id, err := strconv.ParseUint(ctx.Param("id"), 10, 64)
    if err != nil {
        response.BadRequest(ctx, "标签ID非法")
        return
    }
    exists, err := c.tagSvc.TagExists(uint(id))
    if err != nil {
        response.BizError(ctx, err)
        return
    }
    if !exists {
        response.BizError(ctx, errors.NewDefault(errors.CodeResourceNotFound))
        return
    }
    var req dto.ArticleListRequest
    if err := ctx.ShouldBindQuery(&req); err != nil {
        response.BadRequest(ctx, "参数错误")
        return
    }
    req.TagID = uint(id)
    result, err := c.articleSvc.ListArticles(req)
    if err != nil {
        response.BizError(ctx, err)
        return
    }
    response.Success(ctx, result)
}
```

## 5. 对接现有基建

**依赖注入**（`internal/app/app.go` 的 `initDependencies()`，注释占位处追加）：
```go
tagRepo := repository.NewTagRepository(a.mysqlDB)
tagSvc  := service.NewTagService(tagRepo)
// articleSvc 已在首页/分类模块创建，这里复用同一个实例
a.router = api.NewRouter(articleSvc, authorSvc, categorySvc, tagSvc)
```

**路由注册**（`internal/api/router.go`）：在 `Router` 增加 `tagCtrl` 字段，`NewRouter` 注入 `tagSvc`，并在 `Setup` 中 `r.tagCtrl.RegisterRoutes(apiGroup)`。

## 7. 与首页/分类模块的关系 / 待确认

- **与首页标签的关系**：首页侧边栏标签云复用 `GET /api/v1/tags`；点击标签跳转到标签页 `GET /api/v1/tags/:id/articles`。
- **与分类模块的关系**：完全同构（列表 + 下辖文章流），差别仅在关联表——分类用 `articles.category_id` 直连，标签经 `article_tags` 多对多。
- **是否要标签详情接口** `GET /api/v1/tags/:id`：`Tag` 实体只有 `name`，列表已含名称与文章数，暂不需要独立详情接口。
- **标签下是否支持 `category_id` / `keyword` 二次筛选**：本设计未包含，如需可扩展 `TagArticles` 参数。
- 后台 Admin 的标签 CRUD 属于管理端，不在本前台文档范围。
