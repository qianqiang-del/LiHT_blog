# 前台分类模块接口设计

> 版本：v1.0
> 范围：前台 Web 端「分类模块」（分类导航/侧边栏 + 分类文章列表页）
> 关联原型：`prototype-final.html`
> 约定：**响应 / 错误码 / 分页全部复用基建**（`pkg/response`、`pkg/errors`、`response.PageRequest/PageResponse`），与首页接口设计（v1.2）风格一致。

---

## 1. 基建约定（必须复用，禁止自定义）

- **统一响应**：`response.Success(c, data)` → `{ "code": 0, "message": "成功", "data": ... }`
- **错误**：`response.BadRequest(c, msg)`（400）、`response.BizError(c, err)`（业务错误，取 `BizError.Code/Message`）
- **分页请求**：`response.PageRequest{ Page int(form:"page"), Size int(form:"size") }`，**`page`/`size` 标注 `required`，前端必传**
- **分页响应**：`response.PageResponse{ List, Total, Page, Size, TotalPage }`，由 `response.NewPageResponse(list, total, page, size)` 构造
- **错误码**：`errors.CodeSuccess=0`、`CodeBadRequest=400`、`CodeResourceNotFound=3001`、`CodeInternalError=500`；业务错误用 `errors.New(code, msg)` / `errors.NewDefault(code)`

> 分类列表不分页（数据量小），用普通 GET；分类文章列表复用 `response.PageRequest` 分页。

---

## 2. 接口契约（2 个核心 GET，均为公开接口）

基础前缀：`/api/v1`

### 2.1 分类列表（导航 / 侧边栏）

`GET /api/v1/categories`

**说明**：返回全部分类及其已发布文章数，按 `id` 升序（实体无 `sort` 字段，即创建顺序）。

**Response（data 为 `[]CategoryItem`）**
```json
{
  "code": 0,
  "message": "成功",
  "data": [
    { "id": 1, "name": "前端", "article_count": 12 },
    { "id": 2, "name": "后端", "article_count": 8 }
  ]
}
```

`CategoryItem` 结构：
```json
{ "id": 1, "name": "前端", "article_count": 12 }
```

### 2.2 分类下的文章列表（分类详情页）

`GET /api/v1/categories/:id/articles`

**路径参数**

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | uint | 是 | 分类 ID |

**Query 参数（复用 `response.PageRequest`）**

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `page` | int | 是 | 页码 |
| `size` | int | 是 | 每页条数，≤100 |
| `sort` | string | 否 | `latest`（默认，按 `published_at` 倒序）/ `hot`（按 `hot` 倒序） |

**Response（data 为 `response.PageResponse`，`list` 为 `[]ArticleListItem`）**
```json
{
  "code": 0,
  "message": "成功",
  "data": {
    "list": [ /* ArticleListItem[] */ ],
    "total": 12,
    "page": 1,
    "size": 10,
    "total_page": 2
  }
}
```

> `ArticleListItem` 结构见首页接口设计文档 §2.4（含 `category`/`tags`/`author`/三个计数/`hot`）。
> 只查 `status=1`（已发布）；分类不存在返回 `CodeResourceNotFound`。

## 4. 分层实现设计

### 4.1 新增目录结构

```
internal/
  dto/
    category.go      # CategoryItem（新增）
    article.go       # ArticleListRequest / ArticleListItem（已存在，复用）
  repository/
    category_repository.go  # 分类 + 文章数统计（新增）
  service/
    category_service.go      # 分类列表 / 校验存在（新增）
  api/
    category_controller.go   # 2 个 GET 的 controller（新增）
```

> 文章查询复用现有 `ArticleService.ListArticles(req)`（`article_repository.ListPublished` 已支持 `category_id` 筛选）。

### 4.2 DTO（`internal/dto/category.go`）

```go
package dto

type CategoryItem struct {
    ID           uint  `json:"id"`
    Name         string `json:"name"`
    ArticleCount int64 `json:"article_count"`
}
```

### 4.3 Repository 层

```go
// repository/category_repository.go
type CategoryRepository interface {
    // 全部分类 + 各分类「已发布」文章数（一条 SQL 用 GROUP BY category_id 聚合）
    ListWithCount() ([]dto.CategoryItem, error)
    // 校验分类是否存在（供 :id/articles 使用）
    Exists(id uint) (bool, error)
}
func NewCategoryRepository(db *gorm.DB) CategoryRepository
```

> `ListWithCount` 实现示例：
> ```sql
> SELECT c.id, c.name, COUNT(a.id) AS article_count
> FROM categories c
> LEFT JOIN articles a ON a.category_id = c.id AND a.status = 1
> GROUP BY c.id, c.name
> ORDER BY c.id ASC;
> ```

### 4.4 Service 层

```go
// service/category_service.go
type CategoryService interface {
    ListCategories() ([]dto.CategoryItem, error)
    CategoryExists(id uint) (bool, error)
}
```

> 分类文章列表**不**在此新增方法，直接复用 `ArticleService.ListArticles`：
> controller 构造 `dto.ArticleListRequest{ PageRequest:{page,size}, Sort:sort, CategoryID:id }` 调用即可。

### 4.5 Controller 层（全部走 `pkg/response`）

```go
// api/category_controller.go
type CategoryController struct {
    categorySvc service.CategoryService
    articleSvc  service.ArticleService
}
func NewCategoryController(categorySvc service.CategoryService, articleSvc service.ArticleService) *CategoryController
func (c *CategoryController) RegisterRoutes(g *gin.RouterGroup) {
    g.GET("/categories", c.ListCategories)                  // 2.1
    g.GET("/categories/:id/articles", c.CategoryArticles)    // 2.2
}

func (c *CategoryController) ListCategories(ctx *gin.Context) {
    list, err := c.categorySvc.ListCategories()
    if err != nil {
        response.BizError(ctx, err)
        return
    }
    response.Success(ctx, list)
}

func (c *CategoryController) CategoryArticles(ctx *gin.Context) {
    id, err := strconv.ParseUint(ctx.Param("id"), 10, 64)
    if err != nil {
        response.BadRequest(ctx, "分类ID非法")
        return
    }
    exists, err := c.categorySvc.CategoryExists(uint(id))
    if err != nil {
        response.BizError(ctx, err)
        return
    }
    if !exists {
        response.BizError(ctx, errors.NewDefault(errors.CodeResourceNotFound))
        return
    }
    var req dto.ArticleListRequest
    if err := ctx.ShouldBindQuery(&req); err != nil {
        response.BadRequest(ctx, "参数错误")
        return
    }
    req.CategoryID = uint(id)
    result, err := c.articleSvc.ListArticles(req)
    if err != nil {
        response.BizError(ctx, err)
        return
    }
    response.Success(ctx, result)
}
```

## 5. 对接现有基建

**依赖注入**（`internal/app/app.go` 的 `initDependencies()`，注释占位处追加）：
```go
categoryRepo := repository.NewCategoryRepository(a.mysqlDB)
categorySvc  := service.NewCategoryService(categoryRepo)
// 注意 articleSvc 已在首页模块创建，这里复用同一个实例
a.router = api.NewRouter(articleSvc, authorSvc, categorySvc)
```

**路由注册**（`internal/api/router.go`）：在 `Router` 增加 `categoryCtrl` 字段，`NewRouter` 注入 `categorySvc`，并在 `Setup` 中 `r.categoryCtrl.RegisterRoutes(apiGroup)`。

## 7. 与首页模块的关系 / 待确认

- **与首页分类筛选的关系**：首页文章流支持 `GET /api/v1/articles?category_id=X`，与分类页 `GET /api/v1/categories/:id/articles` **底层走同一个 `ArticleService.ListArticles`**，只是路径风格不同。推荐：首页侧边栏点击分类跳转到分类页（RESTful 路径）。
- **是否要分类详情接口** `GET /api/v1/categories/:id`：当前 `Category` 实体只有 `name`，列表已含名称与文章数，详情页通常不需要独立接口；如分类页顶部需要额外信息可后续补。
- **分类下是否支持 `tag_id` / `keyword` 二次筛选**：本设计未包含，如需在分类页内再按标签/关键词过滤，可扩展 `CategoryArticles` 参数。
- 后台 Admin 的分类 CRUD（增删改）属于管理端，不在本前台文档范围。
