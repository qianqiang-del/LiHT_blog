# 前台关于模块接口设计

> 版本：v1.0
> 范围：前台 Web 端「关于页」（博主简介 + 技术栈 + 联系方式 + 博客故事时间线）
> 关联原型：`prototype-final.html`（关于页）
> 约定：**响应 / 错误码 / 分页全部复用基建**（`pkg/response`、`pkg/errors`、`response.PageRequest/PageResponse`），与首页（v1.2）、分类（v1.0）、标签（v1.0）设计风格一致。

---

## 1. 前置条件（实体已定稿）

关于页数据来自两张表：

| 表 | 作用 | 说明 |
|---|---|---|
| `users` | 博主简介 | `nickname` / `avatar` / `bio`（复用首页 `/author` 的博主行） |
| `site_items` | 关于页可配置内容 | 单表 `type` 判别，覆盖四类内容 |

`site_items` 字段语义约定（见 `internal/model/entity/site_item.go`）：

| type | title | content | parent_id | code | icon | sort |
|---|---|---|---|---|---|---|
| `skill_group` | 分组名 | — | — | — | — | ✓ |
| `skill` | 技能名 | — | 所属分组 id | — | — | ✓ |
| `contact` | 展示标签 | 值（如邮箱/链接） | — | github/email/wechat | 图标名 | ✓ |
| `story` | 时间文本 | 故事内容 | — | — | — | ✓ |

> `site_items.sort` 用于管理端排序，展示时按 `sort ASC, id ASC`。

---

## 2. 基建约定（必须复用，禁止自定义）

- **统一响应**：`response.Success(c, data)` → `{ "code": 0, "message": "成功", "data": ... }`
- **错误**：`response.BizError(c, err)`（业务错误）、`response.InternalError(c, msg)`（500）
- **错误码**：`errors.CodeSuccess=0`、`CodeInternalError=500`、`CodeResourceNotFound=3001`
- 关于页是聚合展示接口，**不分页**，不套用 `PageRequest/PageResponse`。

---

## 3. 接口契约（1 个聚合 GET，公开接口）

### 3.1 关于页聚合

`GET /api/v1/about`

**说明**：一次性返回关于页首屏所需全部数据（博主简介 + 技术栈 + 联系方式 + 博客故事），前端只调这一个接口。

**Response（data 为 `AboutResponse`）**
```json
{
  "code": 0,
  "message": "成功",
  "data": {
    "author": {
      "id": 1,
      "nickname": "牵强",
      "avatar": "https://...",
      "bio": "全栈开发者，记录技术与生活"
    },
    "skill_groups": [
      {
        "id": 1,
        "name": "后端",
        "skills": [
          { "id": 3, "name": "Go" },
          { "id": 4, "name": "Gin" }
        ]
      },
      {
        "id": 2,
        "name": "前端",
        "skills": [
          { "id": 5, "name": "Vue" }
        ]
      }
    ],
    "contacts": [
      { "id": 7, "label": "GitHub", "value": "https://github.com/qianqiang", "code": "github", "icon": "github" },
      { "id": 8, "label": "邮箱", "value": "qianqiang@example.com", "code": "email", "icon": "email" }
    ],
    "stories": [
      { "id": 9, "time": "2020-03", "title": "开始写博客", "content": "记录学习与生活的点滴" },
      { "id": 10, "time": "2022-06", "title": "全栈转型", "content": "从后端转向全栈" }
    ]
  }
}
```

**组装规则**
- `author`：`users` 表博主行（`id`/`nickname`/`avatar`/`bio`）
- `skill_groups`：`site_items` 中 `type='skill_group'`，每个分组下挂 `type='skill'` 且 `parent_id = 分组.id` 的技能项
- `contacts`：`type='contact'` 全部项（`title→label`，`content→value`）
- `stories`：`type='story'` 全部项（`title→time`，`content→故事内容`）
- 四类内容均按 `sort ASC, id ASC` 排序；空列表返回 `[]`（不报错）

## 4. 错误响应示例

```json
// 博主资料不存在（理论上初始化时应有，缺省为兜底错误）
{ "code": 3001, "message": "资源不存在" }

// 服务器内部错误（查询失败）
{ "code": 500, "message": "服务器内部错误" }
```

> 注意：`skill_groups` / `contacts` / `stories` 为空时**不报错**，返回空数组。

## 5. 分层实现设计

### 5.1 新增目录结构

```
internal/
  dto/
    about.go             # AboutResponse / SkillGroupDTO / SkillDTO / ContactDTO / StoryDTO（新增）
    author.go            # AuthorProfile 相关（已有，author 字段可复用其结构或精简）
  repository/
    site_item_repository.go   # 按 type 查询 site_items（新增）
    user_repository.go        # GetBlogger（首页模块已有，复用）
  service/
    about_service.go          # 关于页聚合（新增）
  api/
    about_controller.go       # GET /about（新增）
```

### 5.2 DTO（`internal/dto/about.go`）

```go
package dto

type AboutResponse struct {
    Author       AuthorBriefDTO  `json:"author"`
    SkillGroups  []SkillGroupDTO `json:"skill_groups"`
    Contacts     []ContactDTO    `json:"contacts"`
    Stories      []StoryDTO      `json:"stories"`
}

type AuthorBriefDTO struct {
    ID       uint   `json:"id"`
    Nickname string `json:"nickname"`
    Avatar   string `json:"avatar"`
    Bio      string `json:"bio"`
}

type SkillGroupDTO struct {
    ID     uint        `json:"id"`
    Name   string      `json:"name"`
    Skills []SkillDTO  `json:"skills"`
}
type SkillDTO struct {
    ID   uint   `json:"id"`
    Name string `json:"name"`
}

type ContactDTO struct {
    ID    uint   `json:"id"`
    Label string `json:"label"`   // site_items.title
    Value string `json:"value"`   // site_items.content
    Code  string `json:"code"`    // github/email/wechat
    Icon  string `json:"icon"`
}

type StoryDTO struct {
    ID      uint   `json:"id"`
    Time    string `json:"time"`    // site_items.title（时间文本）
    Title   string `json:"title"`   // 标题（story 暂无独立列，可省略或复用 content 首段，待定见 §7）
    Content string `json:"content"` // site_items.content
}
```

> `StoryDTO` 的 `title` 字段：当前实体 `story` 只有 `title=时间文本`、`content=故事内容`，没有独立"故事标题"。若前端需要标题，方案见 §7。

### 5.3 Repository 层

```go
// repository/site_item_repository.go
type SiteItemRepository interface {
    // 按 type 列表查询，返回全部匹配项（内部按 sort ASC, id ASC 排序）
    ListByTypes(types ...string) ([]entity.SiteItem, error)
}
func NewSiteItemRepository(db *gorm.DB) SiteItemRepository
```

> 一次查询即可（`WHERE type IN (?,?,?)`），在 service 内按 type 分组，避免多次请求 DB。

### 5.4 Service 层

```go
// service/about_service.go
type AboutService interface {
    GetAbout() (*dto.AboutResponse, error)
}
```

**组装逻辑（`GetAbout`）**
1. `userRepo.GetBlogger()` → `author`（缺失时返回 `errors.NewDefault(errors.CodeResourceNotFound)`）
2. `siteItemRepo.ListByTypes("skill_group", "skill", "contact", "story")` → 一次拿全
3. 内存分组：
   - `contacts` = 所有 `type=contact`
   - `stories` = 所有 `type=story`
   - `skill_groups` = 所有 `type=skill_group`，并遍历 `type=skill` 按 `parent_id` 挂到对应分组；无归属分组的技能可忽略
4. 空列表用 `make([]T, 0)` 保证序列化为 `[]` 而非 `null`

### 5.5 Controller 层

```go
// api/about_controller.go
type AboutController struct {
    aboutSvc service.AboutService
}
func NewAboutController(aboutSvc service.AboutService) *AboutController
func (c *AboutController) RegisterRoutes(g *gin.RouterGroup) {
    g.GET("/about", c.About)
}
func (c *AboutController) About(ctx *gin.Context) {
    data, err := c.aboutSvc.GetAbout()
    if err != nil {
        response.BizError(ctx, err)
        return
    }
    response.Success(ctx, data)
}
```

## 8. 待确认 / 后续扩展

- **`StoryDTO` 是否需要独立"故事标题"**：当前 `story` 只有 `title=时间文本`、`content=故事内容`。两个可选方案：
  - 方案 A（推荐）：前端直接用 `time` + `content` 渲染（时间线 + 文案），不额外要标题
  - 方案 B：给 `site_items` 加 `extra` 字段存故事标题（需改实体 + 迁移）
- **是否拆分接口**：如需前端按区块懒加载（如技术栈单独加载），可后续加 `GET /api/v1/about/skills` 等，本设计按"一次拉全"处理。
- 关于页内容的**维护**（增删改 site_items）属于后台管理端，不在本前台文档范围。
- 与首页 `/author` 的关系：首页返回带 `stats` 的完整 `AuthorProfile`，关于页只需简介，故用精简的 `AuthorBriefDTO`，两者可复用同一个 `GetBlogger` repo 方法。
